[18] 基于预算分配的混合精度KV缓存压缩算法研究
[20] 摘    要
[21] 大语言模型在长文本问答、代码生成和多轮对话等任务中需要保存大量历史上下文。在自回归解码阶段，模型通常将每个已生成或已输入 token 对应的 Key 和 Value 状态缓存在显存中，以避免重复计算。然而，KV 缓存规模随序列长度、层数、注意力头数量以及并发 batch size 线性增长，在资源受限设备或长上下文推理场景下容易成为主要内存瓶颈。针对传统缓存淘汰方法只在“保留”和“删除”之间进行二元选择的问题，本文提出一种基于预算分配的块级混合精度 KV 缓存压缩算法 BM-KV。该算法首先根据累计注意力贡献、近因权重和前缀约束构造 token 重要性分数，再将连续 token 划分为固定大小的缓存块，并在显存预算下为不同块分配 FP16 保留、INT8 量化保留或淘汰三种动作。为避免低价值 token 因预算剩余被强行保留，算法引入绝对重要性阈值；为降低在线重排开销，算法采用延迟更新机制，在固定步长或查询漂移超过阈值时触发重分配。实验设计以支持较长上下文的小型因果语言模型为基础，从缓存压缩率、困惑度增量、长距离关键词准确率、Decode 阶段每 token 延迟和最大并发 batch size 等方面评价算法效果。本文工作将 KV 缓存管理抽象为带阈值约束的在线预算分配问题，能够为长文本推理场景提供一种无需重新训练大模型的轻量级优化思路。
[22] 关键词：大语言模型；KV缓存；混合精度；预算分配；推理优化
[24] Budget-Aware Mixed-Precision KV Cache Compression Algorithm
[25] Abstract
[26] Large language models rely on key-value cache during autoregressive decoding to avoid redundant computation over previous tokens. However, the memory footprint of KV cache grows linearly with sequence length, number of layers, attention heads, precision and batch size, which makes it a critical bottleneck for long-context inference. To address the limitation of binary keep-or-drop cache eviction, this paper proposes BM-KV, a budget-aware block-level mixed-precision KV cache compression algorithm. BM-KV evaluates token importance using accumulated attention contribution, recency and prefix constraints, groups consecutive tokens into fixed-size cache blocks, and assigns each block to FP16 storage, INT8 storage or dropping under a memory budget. An absolute score threshold is introduced to avoid preserving low-value blocks merely because unused budget remains. A lazy update mechanism is further adopted to reduce online re-ranking overhead. The proposed method is evaluated with long-context lightweight causal language models, using cache compression ratio, perplexity increase, long-range keyword accuracy, time per output token and maximum concurrent batch size as metrics. The work formulates KV cache management as an online budget allocation problem with practical hardware constraints, providing a lightweight post-training optimization strategy for long-context inference.
[27] Key words: Large Language Model; KV Cache; Mixed Precision; Budget Allocation; Inference Optimization

[58] 1 绪    论
[59] 1.1 研究背景
[60] 近年来，大语言模型在自然语言理解、文本生成、代码编写和智能问答等任务中表现出较强的通用能力。与传统判别式模型不同，大语言模型通常采用自回归方式逐 token 生成输出。在每一步解码时，模型需要基于当前 token 的查询向量与历史 token 的键向量和值向量计算注意力分布，从而决定下一步生成内容。为了避免在每一步都重新计算全部历史上下文，推理系统通常将历史 token 的 Key 和 Value 中间状态保存为 KV 缓存。KV 缓存显著降低了解码阶段重复计算量，是当前大语言模型推理优化中最基础的机制之一。
[61] 随着上下文窗口从几千 token 扩展到数十万甚至百万 token，KV 缓存带来的内存压力逐渐成为长文本推理的核心瓶颈。对于一个包含多层 Transformer 解码器的模型，KV 缓存规模与序列长度、模型层数、注意力头数量、每个头的维度、数据精度以及 batch size 均相关。当序列长度增加时，即使模型参数不变，推理阶段需要保留的临时状态也会持续增长。在实际部署中，KV 缓存可能限制并发请求数量，降低服务吞吐量，并导致长文本任务的推理成本明显上升。
[62] 从算法设计角度看，KV 缓存优化可以被理解为一个受限资源下的在线选择问题：在有限显存预算内，系统需要决定哪些历史信息应被完整保留，哪些信息可以低精度保存，哪些信息可以被淘汰。该问题与缓存替换、背包优化、流式数据摘要以及近似注意力计算等经典算法问题具有相似性。因此，对 KV 缓存压缩策略进行建模、设计和实验分析，既能够体现大语言模型系统的底层推理机制，也符合算法设计与分析课程对问题抽象、算法实现和复杂度分析的要求。
[63] 1.2 国内外研究现状
[64] Transformer 模型通过自注意力机制对序列中任意位置之间的依赖关系进行建模[1]。在标准密集注意力中，每个 query 都需要与所有历史 key 计算相似度，因此当输入长度增长时，注意力计算和中间状态存储都会成为效率瓶颈。围绕大语言模型推理效率，已有研究大致可以分为三类：内存管理方法、缓存淘汰方法以及稀疏或压缩注意力方法。
[65] 第一类方法侧重于系统层面的内存管理。vLLM 提出的 PagedAttention 将 KV 缓存划分为固定大小的逻辑块，通过类似操作系统分页的思想减少内存碎片并提升批处理服务吞吐量[2]。这类方法不直接改变注意力计算语义，优势是通用性强，但在极长上下文下仍需要保存大量 KV 状态。
[66] 第二类方法侧重于推理阶段的 KV 缓存淘汰。StreamingLLM 观察到初始 token 在许多模型中具有 attention sink 现象，保留初始 token 与最近窗口可以显著改善单纯滑动窗口在长流式文本中的退化问题[3]。H2O 将一小部分高贡献 token 视为 heavy hitters，并在缓存预算内同时保留近期 token 和高贡献 token[4]。Scissorhands 则利用重要性持久性假设，在测试阶段选择更可能持续影响未来生成的 token，从而降低 KV 缓存占用[5]。这些方法说明，历史 token 对后续生成的重要性并不均匀，缓存策略可以根据重要性进行差异化处理。
[67] 第三类方法侧重于模型结构或注意力机制本身。DeepSeek-V3.2-Exp 的公开资料显示，该模型引入 DeepSeek Sparse Attention，用于探索和验证长上下文训练与推理效率优化，并提供相关开源实现与 kernel 参考[6]。这类方法通常在模型架构或训练阶段引入稀疏注意力约束，能够从源头减少长序列计算成本，但复现门槛和工程依赖较高。本文不试图复现此类大规模架构，而是研究无需重新训练模型的推理阶段缓存压缩策略。
[68] 此外，低比特量化被广泛用于模型权重与激活压缩。LLM.int8() 和 GPTQ 等工作表明，合理的量化策略能够在较小精度损失下显著降低模型存储和计算开销[7-8]。受此启发，KV 缓存也可以不只采用“保留或删除”的二元决策，而是根据 token 重要性采用不同精度存储，以在显存节省和生成质量之间取得更细粒度的平衡。
[69] 1.3 研究意义与本文主要工作
[70] 已有 KV 缓存淘汰方法多数将 token 的处理方式分为保留和淘汰两类。当缓存预算较低时，直接淘汰历史 token 容易破坏长距离依赖；当缓存预算较高时，又难以充分利用低比特表示带来的额外压缩空间。本文认为，KV 缓存优化不应只被看作二元淘汰问题，而应被看作一个多动作预算分配问题。对于高重要性 token，应尽量保留完整精度；对于中等重要性 token，可以接受一定量化误差来换取更低内存；对于低重要性 token，则可以直接淘汰。
[71] 围绕上述思想，本文拟开展以下工作：第一，分析 Transformer 解码阶段 KV 缓存的产生机制和内存开销，将长文本推理中的缓存优化抽象为带容量约束的在线预算分配问题；第二，设计一种具有明确判定规则的重要性感知评分函数，综合历史注意力贡献、近因权重和前缀约束权重评估 token 对后续生成的潜在价值；第三，引入绝对重要性阈值，避免低价值 token 因预算充足而被保留；第四，借鉴分页缓存思想将 token 级动作提升为块级动作，使 FP16、INT8 和淘汰操作能够以连续 Block 为单位执行，从而降低显存碎片化和异构算子调度难度；第五，设计延迟更新机制，减少每步重算分数与排序带来的额外开销。
[72] 本文工作不是复现某一种现有稀疏注意力结构，而是关注无需重新训练大模型的推理阶段缓存压缩策略。与 DeepSeek Sparse Attention 等架构级方法相比，本文方法更强调后处理式、轻量级、可在小模型上验证的算法设计；与传统滑动窗口缓存相比，本文方法通过混合精度动作扩大了缓存预算的利用方式，具有更明确的算法创新点。

[79] 2 KV缓存压缩问题与相关算法原理
[80] 2.1 Transformer自注意力与KV缓存机制
[81] 设输入序列长度为 n，隐藏维度为 d。对于第 l 层 Transformer 解码器，输入隐藏状态经过线性映射得到查询矩阵 Q、键矩阵 K 和值矩阵 V。标准缩放点积注意力可以表示为式（2.1）。
[82] Attention(Q,K,V)=softmax(QK^T / sqrt(d_k))V                                      （2.1）
[83] 在自回归生成中，第 t 步只会新增一个 query，但它需要与从第 1 个 token 到第 t 个 token 的全部 key 计算注意力。若不保存历史 K 和 V，则每一步都需要重新前向计算历史 token 的中间状态，造成大量重复计算。因此，推理框架通常在每层保存历史 K 和 V，形成 KV 缓存。第 t 步生成时只计算当前 token 的 K_t 和 V_t，并与历史缓存拼接。
[84] 若模型共有 L 层，每层有 H 个注意力头，每个头维度为 d_h，序列长度为 n，batch size 为 b，单个数值占用 s 字节，则 KV 缓存理论规模可近似表示为式（2.2）。
[85] Memory_KV = 2 × L × H × d_h × n × b × s                                      （2.2）
[86] 式（2.2）中的系数 2 表示同时保存 Key 和 Value。由该式可知，在模型结构和精度固定时，KV 缓存占用与序列长度 n 和 batch size b 呈线性关系。对于长文本场景，即使模型参数能够被加载到显存中，动态增长的 KV 缓存仍可能导致显存不足。
[87] 2.2 长文本推理中的缓存瓶颈
[88] 长文本推理的典型任务包括长文档问答、代码仓库理解、多轮对话、长篇写作和智能体执行轨迹分析。这些任务往往需要模型在较长上下文中保持对开头指令、关键实体、变量定义和历史约束的记忆。若采用完整 KV 缓存，显存占用会随着上下文长度持续增加；若采用简单滑动窗口，则较早位置的关键信息可能被删除，导致模型无法回答依赖长距离信息的问题。
[89] 例如，在代码生成任务中，函数签名、全局变量定义和输入输出约束通常出现在上下文前部，而具体补全位置可能位于较后位置。若只保留最近窗口，模型可能保留了局部语法上下文，却丢失了函数参数类型和边界条件。类似地，在长文本问答中，答案线索可能位于开头或中间位置，单纯 recent-only 策略难以保证这些 token 被保留。
[90] 因此，KV 缓存压缩算法需要同时考虑三个目标：一是降低缓存内存占用，使推理能够在更长上下文或更高 batch size 下运行；二是尽量保留对后续生成有价值的 token，避免关键信息丢失；三是控制额外计算开销，使缓存选择策略本身不会抵消压缩带来的收益。
[91] 2.3 缓存淘汰、稀疏注意力与量化方法
[92] 最直接的 KV 缓存压缩方法是滑动窗口策略，即只保留最近 w 个 token 的 KV 状态。该方法实现简单，时间开销低，适合局部依赖较强的生成任务。但当生成依赖早期指令或长距离事实时，滑动窗口可能造成明显质量下降。StreamingLLM 在此基础上指出，保留初始 attention sink token 可以显著改善长序列稳定性[3]。
[93] 注意力贡献度策略则根据历史 attention score 判断 token 重要性。H2O 和 Scissorhands 等方法都利用了“少量 token 对注意力贡献较大”这一现象[4-5]。这类方法比滑动窗口更能保留历史关键信息，但通常仍以固定预算下的 token 保留为主要目标。
[94] 稀疏注意力方法从注意力计算图本身减少连接数量。相比推理阶段后处理式淘汰，稀疏注意力可能在训练与推理阶段同时引入结构约束，能够从源头降低长序列计算复杂度。DeepSeek Sparse Attention 即属于这类面向长上下文效率的代表性方向[6]。然而，对课程论文而言，复现大规模稀疏注意力模型训练难度较高，因此本文选择更可控的推理阶段缓存压缩作为研究对象。
[95] 量化方法通过降低数值表示位宽减少存储和计算开销。对于 KV 缓存而言，若将 FP16 的 Key 和 Value 转换为 INT8，则理论上可以将该部分缓存占用约减半。与直接删除 token 相比，量化保留仍能保存部分历史信息，但会引入数值误差。本文将量化与淘汰结合，把 token 处理方式扩展为多动作集合。
[96] 2.4 本文的预算分配模型与复杂度分析
[97] 本文将 KV 缓存压缩建模为带容量约束的多动作预算分配问题。对于历史 token缓存块 j，其重要性价值记为 v_j。系统可以采取三种动作：以 FP16 保留、以 INT8 保留或淘汰。三种动作对应不同成本和不同保真程度。设动作变量 a_j 属于集合 {FP16, INT8, DROP}，成本函数 c(a_j) 分别为 2、1、0 个单位，效用函数 u(j,a_j) 与重要性价值和保真程度共同相关，则优化目标可表示为式（2.3）。
[98] max Σ u(j,a_j),  s.t. Σ c(a_j) ≤ B,  a_j ∈ {FP16, INT8, DROP},  v_j ≥ θ_drop 或 a_j = DROP                 （2.3）
[99] 式（2.3）在传统多选择背包约束外加入了绝对价值阈值 θ_drop。该阈值表示低于最低重要性的 token 或缓存块即使在预算充足时也应被淘汰，从而避免系统保留大量低价值历史状态，造成不必要的访存和计算开销。若对每个候选对象使用动态规划求最优解，时间复杂度与候选数量和缓存预算乘积相关，不适合自回归在线解码。因此，本文采用基于分数排序和阈值过滤的贪心近似策略。
[100] 在工程实现上，逐 token 混合 FP16 与 INT8 会导致内存布局不连续，并且标准 GPU GEMM 算子通常不适合在同一次计算中混合处理不同精度的零散 token。为此，本文后续将候选对象由单个 token 扩展为连续 Block。每个 Block 内 token 使用统一动作，既便于内存页回收，也更接近 PagedAttention 等系统的块式缓存管理思想。
[101] 设当前候选块数量为 m。若每次触发压缩时对所有块排序，时间复杂度为 O(m log m)。若使用堆或近似 top-k 选择，可将动作选择复杂度降低到 O(m log k)。进一步地，本文采用延迟更新机制，并非每个生成步都重新排序，因此均摊到单个 decode step 的额外开销约为 O(m log m / Δ)，其中 Δ 为更新间隔。
[102] 2.5 本章小结
[103] 本章介绍了 Transformer 自注意力与 KV 缓存的基本机制，分析了长文本推理中缓存随序列长度增长带来的内存瓶颈，并比较了滑动窗口、注意力贡献度、稀疏注意力和量化压缩等相关方法。在此基础上，本文将 KV 缓存压缩抽象为多动作预算分配问题，为第3章算法设计奠定基础。
[104] 3 混合精度KV缓存压缩算法设计
[105] 3.1 算法总体框架
[106] 本文提出的算法称为 Budget-aware Mixed-precision KV Cache Compression，简称 BM-KV。BM-KV 的核心思想是在固定缓存预算下，不再简单决定某个 token 是否保留，而是根据重要性将连续 token 块分配到不同存储精度。
[107] BM-KV 的设计重点不是替代 DeepSeek Sparse Attention 这类训练阶段或架构级稀疏注意力机制，而是在不重新训练模型的条件下，对推理阶段已经产生的 KV 缓存进行后处理压缩。算法输入包括当前历史 KV 缓存、各 token 或 Block 的累计注意力贡献、当前位置 t、缓存预算 B、前缀长度 L_prefix、绝对阈值 θ_drop 和延迟更新参数 Δ。算法输出为块级压缩后的 KV 缓存及动作映射表。整体流程包括重要性统计、分数计算、阈值过滤、块级预算分配和延迟缓存更新。

[110] 3.2 Token重要性评分函数
[111] 为了判断历史 token 对后续生成的价值，本文综合三类信号构造重要性评分函数。
[112] 第一类是注意力贡献度 A_i，用于衡量历史 token 在过去若干解码步中被模型关注的程度。A_i 可以通过累积各层各头的 attention score 得到，也可以只统计最后若干层或若干关键头，以降低存储和计算开销。为避免历史 token 因较早生成而被永久高估，A_i 可以采用指数滑动平均方式更新。
[113] 第二类是近因权重 R_i。语言生成具有局部连续性，距离当前生成位置更近的 token 往往对语法连贯和局部语义更重要。因此，本文采用指数衰减函数表示近因权重，如式（3.1）所示。
[114] R_i = exp(-λ(t-i))            （3.1）
[115] 第三类是前缀约束权重 P_i。为使该变量具有明确数学含义，本文将前缀区域定义为位置索引小于 L_prefix 的 token 集合，其中 L_prefix 可以设为固定长度，也可以设为输入总长度的一个比例。P_i 采用阶跃函数表示，如式（3.2）所示。
[116] P_i = 1,  if  i < L_prefix  或  token_i ∈ S_special;   P_i = 0,  otherwise              （3.2）
[117] 式（3.2）中的 S_special 表示特殊标记集合，例如系统提示边界符、函数签名开始符、代码块标识符或用户显式给出的任务约束标记。这样，算法不需要主观判断“哪些 token 是前缀”，而是通过位置阈值和特殊标记集合进行确定。综合上述三类信号，token i 的重要性分数定义为式（3.3）。
[118] Score_i = α_t·Norm(A_i) + β_t·Norm(R_i) + γ_t·P_i                      （3.3）
[119] 其中 Norm 表示归一化操作，α_t、β_t、γ_t 分别控制注意力贡献、近因信息和前缀约束的重要程度。与固定超参数相比，下标 t 表示这些权重可以随生成阶段变化。本文基础实验中先采用固定权重，便于控制变量；在讨论与展望中进一步考虑动态权重分配，例如随着生成步数增加逐渐衰减 γ_t 并提升 β_t，使算法从“保护初始任务约束”逐步过渡到“强化局部连贯性”。一种简单的动态设定如式（3.4）所示。
[120] γ_t = γ_0·exp(-ηt),  β_t = β_0 + (1 - exp(-ηt))·β_inc                   （3.4）
[121] 实际实现中，token 级分数还需要聚合为 Block 级分数。对于包含若干连续 token 的缓存块 C_j，本文采用块内平均分数与最大分数加权的方式计算 BlockScore_j，从而既反映整体重要性，也避免单个关键 token 被平均值淹没。
[122] 3.3 基于预算约束的动作选择策略
[123] 设 FP16 存储成本为 2，INT8 存储成本为 1，淘汰成本为 0，总预算为 B。与早期草稿中仅由预算隐式决定 FP16 与 INT8 边界不同，修订后的 BM-KV 同时使用预算约束和绝对阈值约束。若某个缓存块的分数低于 θ_drop，则该块即使在预算尚有剩余时也直接淘汰；若分数高于 θ_fp16 且预算允许，则优先分配 FP16；其余满足 θ_drop 的中等重要性缓存块才进入 INT8 候选集合。
[124] 动作选择可以表示为式（3.5）。其中 θ_fp16 为完整精度保留阈值，θ_drop 为最低保留阈值，二者可以通过验证集网格搜索确定，也可以根据分数分布的分位数自适应设定。
[125] Action_j = FP16，                       if BlockScore_j ≥ θ_fp16 且 budget足够;
[126] INT8, if θ_drop ≤ BlockScore_j < θ_fp16 且 budget足够;
[127] DROP, otherwise      			（3.5）
[128] 该设计解决了两个问题。第一，预算充足时不会无条件保留低价值 token，从而避免无意义的访存和反量化计算。第二，预算紧张时，高分块仍被优先保留为 FP16，中等分块以 INT8 形式扩大上下文覆盖范围。与二元淘汰策略相比，BM-KV 的优势在于中等重要性信息不会被立即删除，而是以较低精度继续参与后续注意力计算。

[144] 3.4 块级缓存管理与延迟更新机制
[145] 在真实推理系统中，逐 token 交错存放 FP16 与 INT8 KV 会带来显存碎片化和异构计算调度问题。标准 GPU 矩阵乘法通常期望输入张量具有连续内存布局和统一数据类型，若在同一次 attention 中混合大量零散 FP16 token 与 INT8 token，不仅需要频繁索引和反量化，还可能导致 kernel launch 增多，抵消压缩收益。因此，本文将基本管理单元由 token 调整为连续 Block。
[146] 设每个 Block 包含 g 个连续 token，例如 g = 16。一个 Block 内部所有 token 使用相同动作：FP16、INT8 或 DROP。这样可以使 FP16 Block 与 INT8 Block 分别存放在相对连续的内存池中，DROP Block 对应的缓存页则进入回收池。该设计借鉴 PagedAttention 将 KV 缓存划分为固定大小页的思想，但本文进一步在页级别增加精度状态，使混合精度策略更容易与底层内存管理对接。
[147] 除了内存布局，在线重排开销也是 BM-KV 必须处理的问题。如果每生成一个 token 都对过去几千或几万个 token 重新计算衰减函数、聚合分数并排序，额外延迟可能超过节省的 KV 读取时间。为此，本文引入延迟更新机制。算法每隔 Δ 个 decode step 才触发一次完整重排；在间隔内仅追加新 token 的 KV 并复用上一次动作映射。若当前查询向量与上一次更新时的查询均值差异较大，则提前触发更新。
[148] 查询漂移可以用余弦距离表示，如式（3.6）所示。当 d_t 大于阈值 δ 时，说明当前生成状态发生明显变化，历史 token 的重要性排序可能失效，需要重新计算缓存分配。
[149] d_t = 1 - cos(q_t, q_last_update)                                                （3.6）
[150] 通过块级管理与延迟更新，BM-KV 从纸面上的 O(n log n) 排序算法转化为更接近真实推理系统的缓存维护策略。虽然本文课程实验不实现定制 CUDA kernel，但在算法描述中明确这些底层约束，有助于避免将混合精度 KV cache 简化为不现实的逐 token Python 列表操作。
[151] 3.5 算法实现流程与核心代码
[152] 在实现层面，BM-KV 需要维护四类数据结构：一是按层保存的 KV 张量；二是 Block 到 token 范围的映射表；三是每个 Block 的累计注意力贡献度和近因统计；四是动作映射表，用于记录 Block 当前采用 FP16、INT8 还是 DROP。若使用 HuggingFace 小型因果语言模型，可通过 output_attentions=True 获取 attention 权重，并在生成过程中对历史 token 或 Block 的注意力贡献进行滑动累积。
[153] INT8 量化可采用对称量化。对于某个 Block 内的 KV 张量 x，先根据最大绝对值计算缩放因子 s，再将 x/s 四舍五入并截断到 [-127,127] 范围，得到整数表示 q。反量化时使用 q×s 近似原始张量。该过程如式（3.7）所示。
[154] q = clip(round(x/s), -127, 127),   x_hat = q × s                             （3.7）

[157] # block_scores: Tensor[num_blocks]，每个元素对应一个连续KV Block的分数
[158] valid_mask = block_scores >= theta_drop
[159] scores = block_scores.masked_fill(~valid_mask, -float("inf"))

[163] fp16_mask = (block_scores >= theta_fp16) & valid_mask

[166] break

[173] 3.6 算法复杂度分析
[174] 设当前候选 token 数量为 n，Block 大小为 g，则候选块数量约为 m = ceil(n/g)。若直接从所有层所有头累积注意力贡献，统计开销约为 O(LHm)。实际实现中可以只统计最后一层或最后若干层，从而降低常数。分数计算对每个 Block 执行一次，时间复杂度为 O(m)。若采用完整排序进行动作分配，单次更新复杂度为 O(m log m)；若只需要选择高分块，可采用堆或快速选择算法将复杂度降低为 O(m log k)。
[175] 由于 BM-KV 引入延迟更新机制，并非每个生成步都执行完整重排。若每 Δ 步触发一次重排，则动作选择的均摊复杂度约为 O(m log m / Δ)。在 Δ 较大且查询漂移较小时，额外开销会明显低于逐步重排。需要注意的是，Δ 不能无限增大，否则旧的重要性排序可能滞后于当前生成状态。实验中应记录不同 Δ 对 TPOT 和生成质量的影响。
[176] 空间复杂度方面，BM-KV 需要额外保存每个 Block 的重要性分数、动作标记和页表信息，额外空间为 O(m)。压缩后 KV 缓存空间由 FP16 Block 数量和 INT8 Block 数量共同决定。若 FP16 Block 数量为 m_2，INT8 Block 数量为 m_1，则相对于全部 FP16 缓存的空间占用比例近似为式（3.8）。
[177] Ratio = (2m_2 + m_1) / (2m)                                                （3.8）
[178] 式（3.8）表明，在相同 Block 覆盖数量下，引入 INT8 可以显著降低缓存占用；在相同内存预算下，混合精度方法可以保留更多历史 Block。与逐 token 管理相比，块级管理会带来一定粒度损失，但可以换取更稳定的内存布局和更可实现的底层算子调度。
[179] 3.7 本章小结
[180] 本章提出了 BM-KV 混合精度 KV 缓存压缩算法。修订后的算法不仅通过重要性评分函数评估历史 token 的价值，还明确给出前缀权重 P_i 的判定规则，引入绝对阈值避免低价值 token 被无意义保留，并将逐 token 操作改为块级混合精度管理，以降低显存碎片化和异构算子调度难度。同时，延迟更新机制减少了每步重算和排序带来的在线开销。相比二元淘汰策略，BM-KV 能够更细粒度地利用缓存预算，为长文本推理提供一种无需重新训练模型的轻量级优化思路。

[187] 为了全面评价 KV 缓存压缩效果，本文使用以下指标：
[188] 缓存压缩率，用于衡量压缩后 KV 缓存占用相对于 Full Cache 的比例。

[192] 除质量指标外，修订后的实验增加推理系统指标。大模型服务通常将推理延迟拆分为 Prefill 阶段和 Decode 阶段。Prefill 阶段负责处理输入上下文并构建初始 KV cache，常用首 token 延迟 TTFT（Time To First Token）衡量；Decode 阶段逐 token 生成输出，常用每输出 token 延迟 TPOT（Time Per Output Token）或 tokens/s 衡量。由于 BM-KV 主要作用于历史 KV cache 的保存、读取和压缩，本文重点记录 Decode 阶段 TPOT，同时报告压缩后在固定显存预算下可支持的最大并发 batch size。
[193] 其中，困惑度增量越小，说明压缩对模型预测分布影响越小；关键词准确率越高，说明长距离信息保持能力越强；TPOT 越低或 tokens/s 越高，说明 decode 阶段效率越好；最大并发 batch size 越高，说明显存节省转化为了更强的服务吞吐能力。综合这些指标可以避免只追求压缩率而忽视生成质量，也能避免只看单请求延迟而忽略 KV cache 节省的并发价值。

[195] 本文拟设置五组对比方法。Full Cache 保存全部历史 KV，作为质量上界和内存下界的反面参考。Recent-only 只保留最近窗口，是最简单的压缩 baseline。Attention-only 根据累计 attention score 保留高贡献 token。Full INT8 将全部 KV 缓存统一量化为 INT8，用于观察纯量化策略效果。BM-KV 为本文方法，采用 FP16、INT8、DROP 三类动作。

[205] 4.5 消融实验
[206] 为了验证 BM-KV 中各组成部分的作用，本文设计四类消融实验。第一，去除前缀权重 P_i，观察模型在需要开头指令或关键事实时的表现变化。第二，去除近因权重 R_i，仅依赖注意力贡献度，观察局部生成连贯性是否下降。第三，将 INT8 动作替换为 DROP，退化为二元淘汰策略，观察混合精度设计是否带来额外收益。第四，取消延迟更新并每步重排，比较其 TPOT 与质量变化，用于验证延迟更新的必要性。

[211] 5 总结与展望
[212] 5.1 全文总结
[213] 本文围绕大语言模型长文本推理中的 KV 缓存内存瓶颈，提出了一种基于预算分配的混合精度 KV 缓存压缩算法。首先，本文分析了 Transformer 解码阶段 KV 缓存的产生机制和内存开销，指出 KV 缓存规模随序列长度线性增长，是长上下文推理的重要限制因素。其次，本文总结了滑动窗口、注意力高贡献 token 保留、PagedAttention、稀疏注意力和量化压缩等相关方法，明确了本文与已有工作的区别。最后，本文将缓存压缩建模为多动作预算分配问题，设计了综合注意力贡献、近因权重和前缀约束的重要性评分函数，并提出 FP16 保留、INT8 量化和淘汰三类动作的混合精度策略。
[214] 从算法角度看，BM-KV 将传统二元缓存淘汰扩展为多精度缓存管理，使中等重要性 token 能够以较低成本继续保留，从而在相同内存预算下覆盖更多历史上下文。该方法不依赖大规模重新训练，适合在小模型或资源受限场景下验证，具有较强的课程实验可实现性。
[215] 5.2 不足与展望
[216] 受限于结课作业的时间较为有限，本文提出的方法仍存在一些不足。第一，重要性评分函数虽然补充了 P_i 的阶跃定义和绝对阈值，但 α_t、β_t、γ_t 在基础实验中仍主要采用人工设定，尚未形成完全自适应的参数学习机制。第二，块级管理虽然更符合底层内存布局，但会牺牲一定 token 级精细度，可能将同一 Block 内的低价值 token 与高价值 token 一并保留。第三，本文采用简单对称 INT8 量化，尚未深入研究 per-head、per-channel 或非对称量化对 KV cache 误差的影响。第四，本文没有实现定制 CUDA kernel，因此对 FP16 Block Pool 与 INT8 Block Pool 的实际融合计算效率在真实应用场景下可能与理论数据有较大差异。
[217] 未来可以从四个方向改进。其一，引入动态权重分配，使 γ_t 随生成步数增加逐渐衰减，而 β_t 随上下文增长逐步提升，以适应生成早期和生成后期的不同需求。其二，引入层敏感度分析，为不同 Transformer 层分配不同缓存预算。其三，将 token 或 Block 级压缩扩展为语义片段级压缩，使缓存保留更加符合文本、代码和函数结构。其四，结合 PagedAttention、FlashAttention 或专用反量化 kernel，在真实推理系统中验证块级混合精度 KV cache 对 TPOT、吞吐量和最大并发 batch size 的影响。
[218] 结    论
[219] 针对大语言模型长文本推理中 KV 缓存占用较高的问题，本文提出了基于预算分配的块级混合精度 KV 缓存压缩算法 BM-KV。该算法通过重要性评分函数评估历史 token 或 Block 对后续生成的价值，并在固定缓存预算下将缓存块分配为 FP16 保留、INT8 量化和淘汰三种处理方式。与传统 Recent-only 或 Attention-only 策略相比，BM-KV 的主要特点在于将“保留或删除”的二元决策扩展为具有绝对阈值约束的多动作预算分配问题，同时通过块级内存管理和延迟更新机制回应了显存碎片化、异构算子调度和每步重排开销等工程现实问题。后续实验可基于 Qwen2.5 或 TinyLlama 等长上下文小模型，从 PPL、关键词准确率、TPOT 和最大并发 batch size 等指标验证算法效果。
